Do not describe audio settings as persisted saves. [Audio state](D:/Work/CZSaidingjianghu/Web/src/services/audio.ts:49), [runtime volume update](D:/Work/CZSaidingjianghu/Web/src/stores/game.ts:1881). [Entry disclosure](D:/Work/CZSaidingjianghu/Web/android/app/src/main/java/com/saidingjianghu/game/PrivacyConsentActivity.java:25).
- Basic acceptance is required to enter; refusal closes the game. It is **not personalized-ad consent**. After acceptance, startup initializes LevelPlay and preloads rewarded ads, before the user chooses a reward button. Ad viewing is optional; initial advertising SDK processing is not limited to actual viewing. [Entry dialog](D:/Work/CZSaidingjianghu/Web/android/app/src/main/java/com/saidingjianghu/game/PrivacyConsentActivity.java:25), [startup](D:/Work/CZSaidingjianghu/Web/src/main.ts:10), [native initialization/preload](D:/Work/CZSaidingjianghu/Web/android/app/src/main/java/com/saidingjianghu/game/OverseasServicesPlugin.java:58).

Unity documents `setCCPA(true)` as the sale/sharing opt-out signal; networks handle it under their own policies. Denied personalized-ad consent does not mean zero collection. ## Rights, retention and deletion scope

- Provide a direct email route to jcgame for access, correction, deletion, objection/restriction, portability or withdrawal requests **where applicable**. The developer can address data it actually holds, such as support mail, but cannot remotely erase an offline save on the user's device or guarantee erasure of independent provider records.
- Explain Android **Settings → Apps → Wuxia Dice → Storage → Clear storage/data** (labels vary) for local erasure. Uninstalling removes the installed app's local data, while backup restoration can restore eligible data later. For backups, direct users to device/Google backup controls; do not claim clearing storage or resetting the advertising ID deletes already-uploaded advertising records. [Android backup/restore documentation](https://developer.android.com/identity/data/autobackup).
- For Unity/ironSource-held data, link the [Unity player privacy policy](https://unity.com/legal/game-player-and-app-user-privacy-policy) and identify **DPO@unity3d.com**; Unity describes access/deletion requests and its ad Data Privacy icon, depending on implementation. Use “where available” for the icon because it was not verified in this exact release. Unity retention is purpose/legal-obligation based; do not invent a single ad-data deadline. [Unity policy, sections 7, 9–10, 17](https://unity.com/legal/game-player-and-app-user-privacy-policy).
- There is no app account to delete. Google's mandatory in-app and external **account** deletion paths are triggered by in-app account creation. A data-deletion guidance page can still explain the local/provider/email scopes accurately. [Google account deletion requirements](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en).

## Publication follow-ups supported by evidence

1. **In-app policy access is absent.** The short entry disclosure has no policy URL; it is not the full policy. Google requires a policy link or policy text inside every app, plus a Play Console URL. Publishing this website does not change release 0.11.2; add accessible policy access in a subsequent app build. Include app/developer identity, contact, actual data/recipients, security practices, and retention/deletion; use a public active non-geofenced HTML URL. [Google User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en).
2. **Keep disclosures consistent with SDK startup.** Do not say advertising data is collected only after a reward-button tap. Do not describe the entry acceptance as advertising personalization permission or claim a withdrawal toggle exists. Unity's own GDPR guidance distinguishes contextual-ad processing from device-access consent and says consent is needed before SDK initialization where ePrivacy applies; the existing accept-or-exit dialog has not been established as a region-appropriate CMP. [Unity GDPR integration guidance](https://docs.unity.com/grow/levelplay/platform/legal-resources/ironsource-gdpr-compliance). This is an implementation review item, not a finding that this website can resolve it.
3. **Reconcile Firebase wording.** The entry dialog mentions Firebase, but the current release disables it. The published policy must say current Firebase Analytics/Crashlytics collection is disabled. Before any enabled release, update the policy, entry disclosure and Play Data safety answers to the actual configuration. [Release config](D:/Work/CZSaidingjianghu/Web/android/app/build/generated/source/buildConfig/release/com/saidingjianghu/game/BuildConfig.java:15), [Firebase initialization guard](D:/Work/CZSaidingjianghu/Web/android/app/src/main/java/com/saidingjianghu/game/OverseasFirebase.java:19).
4. **Play Data safety includes SDK processing.** Do not answer “no collection” merely because jcgame has no gameplay backend. Confirm the actual SDK/dashboard configuration and keep the form consistent with the policy. [Google Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en).

## Firebase — future enabled versions only

The existing optional implementation would enable analytics storage after basic acceptance while denying ad storage, ad user data and ad personalization. It logs ad lifecycle/placement/failure events and impressions with network, format and available revenue; Crashlytics receives distribution/provider keys. This is dormant in 0.11.2. [Optional implementation](D:/Work/CZSaidingjianghu/Web/android/app/src/main/java/com/saidingjianghu/game/OverseasFirebase.java:19).

If enabled in a future build, Analytics disclosures should cover app-instance IDs, app lifecycle/usage and configured ad events, device information and approximate geography; respect the code's disabled ad-ID collection and denied advertising consents. Crashlytics would cover crash traces, relevant app/device state and installation/session identifiers for debugging. [Analytics Android disclosure](https://support.google.com/analytics/answer/11582702), [Firebase Android disclosure](https://firebase.google.com/docs/android/play-data-disclosure), [Firebase privacy/security](https://firebase.google.com/support/privacy). Do not present these as current collection or promise Firebase controls that are not implemented.
